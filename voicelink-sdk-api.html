Telephony · Voice AI · Python SDK

VoiceLink SDK

Bind VoiceLink phone numbers to voice-AI agents — inbound and outbound — through one clean, typed Python interface. Ships native integrations for LiveKit and Pipecat.

$ pip install voicelink[livekit]

01 — Overview

Two integration models, one core

The SDK is a thin, typed layer over VoiceLink's REST API plus purpose-built helpers for each agent framework. The core handles auth, numbers, trunks, routing, bots, and calls. Each integration adds only what its framework needs — nothing more.

LiveKit

connection: SIP trunk

LiveKit runs its own SIP service, so this integration is configuration only — no media code. The SDK provisions both sides of the trunk and the dispatch rule. Because LiveKit Cloud is TLS-only and VoiceLink speaks plain SIP, calls route through a small SIP bridge you run.

Pipecat

connection: real-time media

Pipecat has no telephony of its own — it expects raw audio over a WebSocket. The SDK ships a frame serializer that translates between VoiceLink's wire format and Pipecat, plus a provisioner that registers the bot and routes the number. No SIP, no bridge.

FrameworkConnectionSDK providesMedia code
LiveKitSIP trunkProvisioning helpersNone
PipecatWebSocketFrame serializer + provisionerBuilt once

02 — Install

Install

The core has no framework dependencies. Add an extra only for the integration you use.

bash
# core only — auth, trunks, routing, bots, calls, DIDs
pip install voicelink

# with an integration extra
pip install voicelink[livekit]
pip install voicelink[pipecat]

03 — Authenticate

Authenticate

Log in with a username / password, or construct the client directly from an API token. client_id is required for reseller accounts (the client the number belongs to).

python
from voicelink import VoiceLinkClient, UAT_BASE_URL

# UAT / testing
vl = VoiceLinkClient.login("USER", "PASS", base_url=UAT_BASE_URL, client_id=123)

# Production — omit base_url (defaults to app.voicelink.co.in/api)
# vl = VoiceLinkClient.login("USER", "PASS", client_id=YOUR_CLIENT_ID)

# Or from an existing token
# vl = VoiceLinkClient("TOKEN", base_url=UAT_BASE_URL, client_id=123)

The five you need to connect a number to an agent are vl.sip_trunks, vl.routing, vl.calls, vl.websocket_bots and vl.dids; the client carries twenty-one namespaces in all — see Full REST API. Call vl.close() when done.

Core API

SIP Trunks

A trunk connects a number to a SIP endpoint — your bridge, or a preset bot provider. For LiveKit you create a custom trunk pointing at your bridge.

sip_trunks.create_custom(...)custom host / port / transport / codecs / credentials
sip_trunks.update(id, ...)repoint host / port / transport / codecs
sip_trunks.list()page of trunks (incl. username, registration_password)
sip_trunks.create_for_bot_provider(...)preset provider (VAPI / Retell / …)
python
from voicelink.enums import SipCodec, TransportType

trunk = vl.sip_trunks.create_custom(
    trunk_name="livekit-bridge",
    sip_server_host="203.0.113.10",   # your bridge
    sip_server_port=35060,              # required
    transport_type=TransportType.UDP,
    audio_format=[SipCodec.ALAW],
    # supply your own credentials so the bridge can authenticate outbound:
    username="trunk_mybridge",
    registration_password="A-STRONG-SECRET",
)
print(trunk.id, trunk.username, trunk.registration_password)

note

sip_server_host must be unique across your trunks. If you supply username/registration_password, the bridge uses those same credentials to authenticate outbound calls — so pick them yourself rather than letting them auto-generate.

Core API

Call Routing

One rule per number binds its inbound and outbound handlers. A handler is a SIP trunk, a WebSocket bot, or (outbound only) “only answer”.

routing.create(...)bind a DID to inbound + outbound handlers
routing.update(id, ...)change direction / trunk / bot assignment
routing.list()rules for the account / client
python
from voicelink.enums import InboundRoute, OutboundRoute

vl.routing.create(
    did_number="919876543210",
    inbound=InboundRoute.SIP_TRUNK,   inbound_sip_trunk_id=trunk.id,
    outbound=OutboundRoute.SIP_TRUNK, outbound_sip_trunk_id=trunk.id,
)

Core API

Outbound Calls

VoiceLink-initiated outbound (the add_lead queue): VoiceLink dials the customer and connects them to the number's outbound handler. Used with the WebSocket-bot / Pipecat path.

calls.create(did_number, customer_number, ...)queue a single outbound lead
calls.create_bulk(did_number, leads)queue many (async job)
python
res = vl.calls.create(
    did_number="919876543210",
    customer_number="9000000002",   # national number — no country code
    country_code="91",              # supplied separately
    custom_parameters={"campaign": "fall"},
)
print(res.outbound_queue_id)

🔒  pass the country code separately

VoiceLink builds the dial string from customer_number plus country_code. A number with the country code already inside it and no country_code produces a string the carrier cannot route, and the call fails with 38 - Network out of order — which reads like a dead carrier rather than a malformed request. Verified live: "919000000001" alone failed with cause 38; "9000000001" with country_code="91" connected normally. PipecatProvisioner.place_call() strips a duplicated code defensively, but calls.create() does not — supply both fields.

Core API

WebSocket Bots

A bot endpoint VoiceLink streams live call audio to over WebSocket — the Pipecat path. l16_16k (16 kHz linear PCM) is the recommended format for speech pipelines.

websocket_bots.create(bot_name, websocket_url, ...)register a streaming bot
websocket_bots.update(id, ...)change URL / format / status
websocket_bots.list()page of bots
python
from voicelink.enums import AudioFormat

bot = vl.websocket_bots.create(
    bot_name="Support",
    websocket_url="wss://your-server/ws",
    audio_format=AudioFormat.L16_16K,
)

Core API

Webhooks

VoiceLink POSTs JSON to your configured webhook URL as a call progresses. parse_webhook() turns the raw body (string, bytes, or dict) into a typed WebhookEvent. Always respond 200 after handling, or VoiceLink may retry.

parse_webhook(body) → WebhookEventparse a raw webhook body into typed objects
python
from voicelink.webhooks import parse_webhook
from voicelink.enums import CallEvent

# inside your web handler (Flask / FastAPI / etc.)
event = parse_webhook(request_body)      # str, bytes, or dict

if event.event is CallEvent.COMPLETED:
    c = event.call
    print(c.id, c.from_number, "->", c.to_number,
          c.status, c.duration_sec, "queue:", c.outbound_queue_id)

return 200   # always ack, or VoiceLink retries

Event types

The public docs list a flat payload; the real one nests the call under a call key — the SDK maps the delivered shape. event.event is a CallEvent (unknown types pass through as a string).

CallEventFires when
INITIATEDcall created / queued
RINGINGthe far end is ringing
ANSWEREDthe call was picked up
ENDEDthe call hung up
FAILEDthe call could not complete
COMPLETEDterminal event — fires even for failed calls (status carries the outcome)

event.call fields

FieldMeaning
idVoiceLink call id
directioninbound / outbound
from_number · to_numbercaller and callee
status · call_statuscall outcome
sip_status · hangup_cause · hangup_reasonSIP / Q.850 detail
started_at · ringing_at · answered_at · ended_atlifecycle timestamps

note

Set the destination with webhook_url= when you create the bot (or on the routing). RINGING and FAILED are emitted by the platform but absent from the public docs.

Integration

LiveKit  Configuration only

Provision both sides of a LiveKit SIP connection and place agent calls. LiveKit terminates SIP and RTP itself — this layer never touches call audio.

create_inbound_trunk(name, numbers, allowed_addresses)accept calls from your bridge
create_dispatch_rule(trunk_ids, agent_name, room_prefix)room per call + dispatch agent (inbound)
create_outbound_trunk(name, address, numbers, transport, codecs)dial out via your bridge
dispatch_agent(room_name, agent_name)put the agent in an outbound room
place_call(sip_trunk_id, call_to, room_name, participant_identity)ring a number into a room

Inbound — caller → agent

python
from voicelink.integrations.livekit import LiveKitProvisioner
from voicelink.enums import SipCodec, TransportType, InboundRoute, OutboundRoute

async with LiveKitProvisioner(
    livekit_url="wss://YOURPROJECT.livekit.cloud",
    api_key="LK_KEY", api_secret="LK_SECRET", voicelink=vl,
) as prov:
    trunk = await prov.create_inbound_trunk(
        name="voicelink-inbound",
        numbers=["919876543210"],
        allowed_addresses=["203.0.113.10/32"],   # SECURITY: only your bridge
    )
    await prov.create_dispatch_rule(
        trunk_ids=[trunk.sip_trunk_id],
        agent_name="voice-assistant", room_prefix="call-",
    )
    # VoiceLink side: trunk -> bridge, route the DID to it
    vlt = prov.create_voicelink_trunk(
        trunk_name="livekit-inbound",
        sip_server_host="203.0.113.10", sip_server_port=35060,
        transport_type=TransportType.UDP, audio_format=[SipCodec.ALAW],
        username="trunk_in", registration_password="SECRET",
    )
    vl.routing.create(
        did_number="919876543210",
        inbound=InboundRoute.SIP_TRUNK,  inbound_sip_trunk_id=vlt.id,
        outbound=OutboundRoute.SIP_TRUNK, outbound_sip_trunk_id=vlt.id,
    )

Outbound — agent → callee

python
async with LiveKitProvisioner(...) as prov:
    trunk = await prov.create_outbound_trunk(
        name="voicelink-outbound",
        address="203.0.113.10:35060",   # your bridge, not VoiceLink directly
        numbers=["919876543210"],
        transport=TransportType.UDP, codecs=[SipCodec.ALAW],
    )
    await prov.dispatch_agent(room_name="outbound-1", agent_name="voice-assistant")
    await prov.place_call(
        sip_trunk_id=trunk.sip_trunk_id,
        call_to="+919876543210",          # country code required
        room_name="outbound-1", participant_identity="callee",
        wait_until_answered=False,
    )

🔒  security — lock the inbound trunk

Your LiveKit project has a public SIP address. Never leave an inbound trunk at allowed_addresses=["0.0.0.0/0"] with no auth — SIP scanners will find it and flood it with fake calls, each spinning up a room and an agent that runs up your bill. Always restrict to your bridge IP and your DID.

Integration

Pipecat  Media serializer

The mirror image of LiveKit: no SIP, no bridge. VoiceLink streams call audio to your Pipecat server over WebSocket, and the SDK's serializer translates the wire format both ways.

Provision the number

PipecatProvisioner registers the bot and routes the DID in one idempotent call. It returns a Provisioned record of what changed (safe to re-run).

setup_inbound(bot_name, websocket_url, did, ...)register bot + route inbound
setup_outbound(bot_name, websocket_url, did, ...)register bot + route outbound
place_call(did, customer_number, country_code, ...)dial out (add_lead)
restore_previous(provisioned)undo a change made in this process
restore_sip_trunk(did, sip_trunk_id, inbound, outbound)hand a DID back to a SIP trunk, either or both directions
route_inbound_to_bot(did, bot_id) · route_outbound_to_bot(did, bot_id)change one direction, leaving the other untouched
ensure_bot(bot_name, websocket_url, ...)create or update the bot only, without routing
find_bot(bot_name) · find_routing(did)read-only lookups
python
from voicelink.integrations.pipecat import PipecatProvisioner

prov = PipecatProvisioner(vl)
p = prov.setup_inbound(
    bot_name="Support",
    websocket_url="wss://your-pipecat-server/ws",
    did="919876543210",
)
print(p.bot.id, p.routing.id, p.bot_created)

Wire the serializer into your Pipecat pipeline

VoiceLinkFrameSerializer plugs into a Pipecat WebSocket transport — it handles VoiceLink's JSON-with-base64-G.711 dialect so your pipeline sees plain audio frames.

python
from voicelink.integrations.pipecat import VoiceLinkFrameSerializer

serializer = VoiceLinkFrameSerializer()

# pass it to your Pipecat WebSocket transport params:
#   FastAPIWebsocketParams(serializer=serializer, ...)
# the transport now speaks VoiceLink; your pipeline stays standard.

note

Requires the extra: pip install voicelink[pipecat]. For outbound, the DID's outbound handler must point at an active WebSocket bot — add_lead refuses to dial otherwise. Pipecat's FastAPI transport needs its own extra: pip install "pipecat-ai[websocket]".

audio format is advisory

The audio_format you set on the bot is not necessarily what VoiceLink streams. A bot configured l16_16k was observed sending audio/alaw at 8 kHz — confirmed twice: in the raw frames, and by every media frame being exactly 160 bytes (16 kHz PCM would be 640). VoiceLinkFrameSerializer therefore reads media_format from each call's start frame at runtime and adapts, so a mismatch is harmless. Do not rely on the configured value in your own code.

restoring a shared number

restore_previous(p) only works inside the same process, since p lives in memory. To hand a DID back in a later run — the usual case when a number is shared with a LiveKit deployment — use restore_sip_trunk(did=…, sip_trunk_id=…), which restores both directions by default. Restoring only inbound leaves outbound calls still routed to the bot.

🔒  leave “WebSocket API” switched OFF

The bot's WebSocket API toggle in the portal must stay off. With it on, VoiceLink answers the call and hangs up in under a second without ever opening the media WebSocket — verified by A/B test on a live call (cause code 32, zero frames received). The REST API exposes no field for it, so the SDK cannot set it; bots inherit the platform default. If a bot receives no audio, check this toggle first.

the SIP bridge

LiveKit's TLS-only SIP is the sole reason the bridge exists. It terminates VoiceLink's plain SIP and re-originates to LiveKit over TLS (inbound), and authenticates to VoiceLink's termination server (outbound). It is infrastructure you run — see the separate bridge setup guide.
